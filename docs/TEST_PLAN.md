# 실험 및 검증 계획

## 목적

실험은 이미 동작하는 코드가 있다는 사실을 보여주기 위한 절차가 아니라, 다음 질문에 데이터로 답하기 위해 필요합니다.

- 같은 조건을 반복했을 때 센서 응답이 비슷한가?
- 충격 위치를 바꾸면 가장 가까운 PZT와 추정 좌표가 함께 변하는가?
- 정상 진동·국부 충격·반복 충격·센서 잡음을 구분할 근거가 있는가?
- 현재 임계값이 오검출과 미검출을 과도하게 만들지 않는가?
- 포화, 누락, SD 기록 지연 등 데이터 품질 문제가 없는가?

따라서 실험 전에는 “손상을 진단한다”가 아니라 “상대 충격 위치·크기와 점검 우선순위를 반복성 있게 기록한다”를 검증 목표로 둡니다.

## Gate 0: 실험 시작 전 기능 점검

- [ ] 최종 회로 사진과 핀맵이 일치한다.
- [ ] MPU6050 `0x69`, DS3231 `0x68`, OLED `0x3C`가 인식된다.
- [ ] microSD에 `/impact_log_v3.csv`와 상세 파형 파일이 생성된다.
- [ ] FL/FR/RL/RR을 각각 두드렸을 때 대응 채널이 가장 크게 반응한다.
- [ ] 부팅 보정과 PZT 채널 자가시험을 통과한다.
- [ ] 시리얼 출력과 microSD 이벤트 수가 일치한다.
- [ ] ADC 값이 0 또는 4095에 지속적으로 붙지 않는다.
- [ ] RTC 시간이 실제 시간과 맞거나, RTC 미사용 사실을 기록한다.

하나라도 실패하면 정량 실험을 시작하지 않고 배선·회로·펌웨어를 먼저 수정합니다.

## 1단계: 파일럿 45회

파일럿의 목적은 최종 성능 수치 산출이 아니라 실험 설계와 장비가 유효한지 확인하는 것입니다. 정해 둔 조건표에 따라 총 45회를 수행하고 다음을 점검합니다.

- 조건별 이벤트 검출 여부
- 채널별 기준값·잡음·최대값 분포
- PZT와 IMU의 시간적 일치
- 포화 및 유효하지 않은 이벤트 비율
- 동일 조건 반복 시 점수와 위치의 변동
- SD 요약·파형 누락과 기록 지연
- 수동 라벨과 파일·이벤트 ID 연결 오류

### 파일럿에서 조정 가능한 값

- 센서별 `PZT_GAIN`
- `TRIGGER_FLOOR_COUNTS`
- `NOISE_MULTIPLIER`
- `IMU_CONFIRM_DELTA_G`
- PZT·IMU 정규화 기준
- 점검 권고 및 우선 점검 점수 경계

값을 바꿀 때는 변경 이유, 변경 전후 값, 근거 그래프와 펌웨어 커밋을 남깁니다.

## Gate 1: 본 실험 진입 기준

- [ ] 모든 위치에서 기대 채널 순서가 대체로 유지된다.
- [ ] 반복적으로 포화되는 채널이 없다.
- [ ] 명백한 충격의 미검출과 무충격 오검출 원인이 설명된다.
- [ ] 요약 로그와 상세 파형의 누락 원인이 해결되었다.
- [ ] 조건표·라벨·파일명 규칙을 팀원 모두 같은 방식으로 사용한다.
- [ ] 최종 설정값과 센서 배치를 기록했다.
- [ ] 펌웨어를 본 실험용 버전으로 동결하고 Git 커밋 해시를 남겼다.

## 2단계: 본 실험 270회

파일럿 통과 후 동결된 회로·센서 배치·펌웨어로 총 270회를 수행합니다. 본 실험 중에는 임계값이나 이득을 바꾸지 않습니다. 수정이 불가피하면 기존 결과와 섞지 않고 새 실험 세션과 새 버전으로 다시 시작합니다.

매 회차마다 다음을 남깁니다.

- 실험 ID와 펌웨어 커밋
- 실제 조건과 수동 정답 라벨
- 위치, 물체 질량, 높이, 반복 번호
- 이벤트 ID와 요약/파형 파일명
- 실패·재시도·예외 상황

## 평가 지표

- 검출률과 오검출률
- 클래스별 이벤트 수와 라벨 일치율
- 위치 영역 정확도 및 정규화 좌표 오차
- 동일 조건 점수의 평균, 표준편차, 변동계수
- PZT·IMU 포화율과 유효 데이터 비율
- 로그 저장 성공률과 처리 지연 분포

표본 수가 충분하지 않거나 조건이 통제되지 않은 결과는 일반화하지 않습니다. 수치에는 반드시 실험판, 센서 부착, 낙하 조건과 표본 수를 함께 표시합니다.

## 백업 규칙

1. 매 실험 세션 종료 직후 SD 원본을 날짜·세션 폴더로 복사합니다.
2. 원본은 수정하지 않고 읽기 전용 백업을 하나 더 만듭니다.
3. 실험 인덱스와 사진, 설정값, Git 커밋 해시를 같은 세션 폴더에 둡니다.
4. 공개 GitHub에는 개인정보를 제거한 대표 데이터와 분석 결과만 커밋합니다.

## 주장 범위

검증 결과는 사용한 축소 시험판과 조건 안에서만 유효합니다. 실제 전기차 배터리 손상이나 운행 안전을 판정했다는 표현은 사용하지 않으며, “상대 충격 기록”, “위치 추정”, “점검 우선순위 안내”로 한정합니다.
