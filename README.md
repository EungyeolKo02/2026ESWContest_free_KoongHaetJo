# EV-BLACKBOX Firmware

> ESP32 기반 EV 배터리팩 충격·진동 블랙박스

**제24회 임베디드SW경진대회 자유공모 부문 · 팀명 쿵했조**

EV-BLACKBOX는 축소 시험판에 부착한 PZT 센서 4개와 MPU6050을 이용해 충격을 감지하고, ESP32에서 상대 위치와 크기, 점검 우선순위를 계산하는 연구용 프로토타입입니다. DS3231 RTC로 발생 시각을 남기고, 사건 요약과 충격 전 0.5초·후 1.0초의 센서 파형을 microSD에 함께 저장합니다.

이 시스템의 목적은 순간적인 충격을 나중에 다시 확인할 수 있는 기록으로 바꾸는 것입니다. 실제 EV 배터리의 손상이나 주행 안전을 직접 판정하지 않으며, 축소 시험판 안에서 의심 구역의 후속 점검 순서를 정하기 위한 참고 정보를 제공합니다.

## 구현 및 검증 현황

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| 통합 시제품 | 완료 | PZT 4채널·MPU6050·RTC·OLED·microSD·LED·부저 연동 |
| 충격 감지 | 완료 | PZT 1 ms 수집과 IMU 5 ms 교차 확인 |
| 위치·점수 계산 | 완료 | 0~1 상대 좌표, 5개 구역, 0~1 상대 점수 산출 |
| 사건 기록 | 완료 | 요약 CSV와 사건 전후 1.5초 상세 파형 저장 |
| 저하 운용 | 완료 | 주변장치 오류 시 가능한 핵심 기능 유지 |
| 정량 시험 | 완료 | 5개 위치 × 3개 높이 × 5회 반복, 총 75회 |

현재 공개 버전은 `v0.4.1`입니다.

## 시험 구성과 결과

동일한 낙하 물체와 시험판, 센서 배치, 펌웨어를 유지하고 충격 위치와 낙하 높이만 바꿨습니다. 각 회차는 수동 조건 라벨, 요약 CSV, 상세 파형, 영상 시점을 같은 이벤트 ID로 대조했습니다.

- 위치: `FL`, `FR`, `RL`, `RR`, `CENTER`
- 높이: `3 cm`, `5 cm`, `10 cm`
- 반복: 조건별 5회, 총 75회

| 평가 항목 | 목표 | 최종 보고서 결과 |
|---|---:|---:|
| 구역 정확도 | ≥ 85% | **91.7% (66/72)** |
| 평균 좌표 오차 | ≤ 0.15 | **0.09 (N=72)** |
| 높이-점수 상관계수 | ρ ≥ 0.80 | **ρ=0.88** |
| 3<5<10 cm 증가 일관성 | ≥ 80% | **90.9% (20/22)** |
| 반복성 | CV ≤ 15% | **9.8%** |
| ADC 포화율 | ≤ 5% | **2.7%** |
| 검출률 / 오검출률 | ≥ 95% / ≤ 5% | **98.7% / 3.3%** |
| 저장 성공률 | ≥ 99% | **100% (74/74)** |

75회 중 74회를 검출했고, 포화되지 않은 유효 표본 72회로 위치와 강도 성능을 계산했습니다. 높이별 평균 점수는 3 cm `0.28±0.04`, 5 cm `0.49±0.06`, 10 cm `0.78±0.08`로 증가했습니다. 이 결과는 해당 축소 시험판과 실험 조건에만 적용됩니다.

## 주요 기능

- PZT 4채널을 약 1 ms 간격으로 스캔
- MPU6050 가속도를 약 5 ms 간격으로 수집해 PZT 신호를 교차 확인
- 채널별 기준값과 잡음 수준을 부팅 시 자동 보정
- 6단계 상태 흐름으로 초기화·보정·자가시험·감시·수집·재무장 제어
- 충격 전 0.5초와 충격 후 1초의 상세 파형 저장
- 네 PZT의 가중중심을 이용한 상대 충격 위치 추정
- DS3231 RTC가 연결되면 실제 날짜·시간 기록
- OLED, 3색 LED, 능동 부저로 상태 및 점검 우선순위 표시
- microSD 장애 시 최대 8개 이벤트를 메모리에 보관한 뒤 재시도
- 센서 포화, 유효 채널, 장치 상태, 오류 플래그를 함께 기록
- 시리얼 명령으로 상태 확인, 재보정, 자가시험, 수동 라벨 수집 지원
- OLED·RTC·MPU6050·microSD 일부가 없어도 가능한 기능은 계속 수행하는 저하 운용

## 동작 흐름

```text
부팅 → 장치 초기화 → PZT 자동 보정 → 채널 응답 자가시험
     → 대기/감시 → 충격 후보 검출 → PZT·IMU 교차 확인
     → 위치·점수 계산 → 표시/경고 → 요약·파형 저장 → 재무장
```

이벤트는 신호 유효성과 점수에 따라 다음처럼 기록됩니다.

- `IGNORED`: 잡음 또는 유효하지 않은 이벤트
- `RECORD_ONLY`: 기록은 남기지만 즉시 점검 우선순위는 낮음
- `INSPECTION_RECOMMENDED`: 점검 권고
- `PRIORITY_INSPECTION`: 우선 점검 권고

## 개발 환경과 라이브러리

- 보드: ESP32 DevKit V1 / Arduino IDE의 `ESP32 Dev Module`
- 시리얼 속도: `115200 baud`
- 보드 패키지 내장 라이브러리: Wire, SPI, SD

| 구성요소 | 검증 버전 |
|---|---:|
| ESP32 Arduino Core | `3.3.11` |
| Adafruit MPU6050 | `2.2.9` |
| Adafruit SSD1306 | `2.5.17` |
| Adafruit GFX Library | `1.12.6` |
| Adafruit Unified Sensor | `1.1.15` |
| Adafruit BusIO | `1.17.4` |
| RTClib | `2.1.4` |

2026-09-03 `ESP32 Dev Module` 대상으로 컴파일을 확인했습니다. 프로그램 저장공간은 441,110 bytes(33%), 동적 메모리는 66,360 bytes(20%)를 사용합니다.

## 빌드 및 업로드

1. Arduino IDE에 ESP32 보드 패키지를 설치합니다.
2. 라이브러리 매니저에서 위 라이브러리를 설치합니다.
3. `EV_BlackBox_Firmware.ino`를 엽니다.
4. `도구 > 보드 > esp32 > ESP32 Dev Module`을 선택합니다.
5. 연결된 포트를 선택하고 검증한 뒤 업로드합니다.
6. 시리얼 모니터를 `115200 baud`로 엽니다.
7. 부팅 보정 중에는 판과 센서를 만지지 않습니다.
8. 안내에 따라 PZT 네 채널을 한 번씩 가볍게 두드려 응답 자가시험을 완료합니다.

실제 ESP32 보드 업로드, PZT 4채널 매핑, 주변장치 연동, microSD 로그 생성과 75회 정량 시험까지 확인했습니다.

## 시리얼 명령

| 명령 | 기능 |
|---|---|
| `h` | 도움말 출력 |
| `s` | 장치 상태와 현재 센서값 출력 |
| `d` | RTC 재연결을 시도하고 현재 날짜·시간 출력 |
| `c` | PZT 재보정 후 채널 응답 자가시험 |
| `v` | PZT 채널 응답 자가시험만 다시 실행 |
| `t` | 모의 `INSPECT` 이벤트 생성 |
| `r` | microSD 재초기화 및 보관 이벤트 쓰기 재시도 |
| `g` | 라벨이 지정된 1.5초 데이터 구간 수동 수집 |
| `0` | 다음 이벤트를 `UNCLASSIFIED_IMPACT`로 라벨링 |
| `1` | 다음 이벤트를 `NORMAL_VIBRATION`으로 라벨링 |
| `2` | 다음 이벤트를 `LOCAL_IMPACT`로 라벨링 |
| `3` | 다음 이벤트를 `REPEATED_SHOCK`로 라벨링 |
| `4` | 다음 이벤트를 `SENSOR_NOISE`로 라벨링 |

숫자 라벨은 데이터셋 구축을 위한 수동 정답표이며 자동 분류 결과가 아닙니다.

## microSD 기록

카드 루트에는 다음 파일이 생성됩니다.

- `/impact_log_v3.csv`: 이벤트당 한 행의 요약 로그
- `/tr_...csv`: 이벤트 전후의 PZT·가속도 상세 파형

RTC가 정상 연결되면 실제 날짜와 시간을 기록하고, RTC가 없으면 부팅 후 경과 시간을 사용합니다. SD 쓰기에 실패해도 요약 행을 시리얼에 출력하고, RAM 큐에 최대 8개 이벤트를 보관해 재연결 후 기록을 시도합니다. 자세한 필드는 [docs/LOG_FORMAT.md](docs/LOG_FORMAT.md)를 참고합니다.

## 핵심 핀맵

| 기능 | ESP32 GPIO |
|---|---:|
| PZT Front-Left / Front-Right | 32 / 33 |
| PZT Rear-Left / Rear-Right | 34 / 35 |
| I2C SDA / SCL | 21 / 22 |
| 능동 부저 | 25 |
| 초록 / 노랑 / 빨강 LED | 26 / 27 / 14 |
| microSD SCK / MISO / MOSI / CS | 18 / 19 / 23 / 13 |

DS3231은 I2C 주소 `0x68`을 사용합니다. 주소 충돌을 피하려면 MPU6050의 AD0를 3.3V에 연결해 `0x69`로 사용합니다. 전체 배선과 회로 주의사항은 [docs/HARDWARE.md](docs/HARDWARE.md)에 정리했습니다.

## 펌웨어 판정 기준

최종 보고서에 사용한 주요 설정값은 다음과 같습니다.

- 충격 트리거: `baseline + max(120, noise × 8)`
- IMU 확인 기준: 기준 중력 대비 `0.20 g`
- 점수 정규화: PZT `4095 counts`, IMU `10.0 g`
- 점검 권고 점수: `0.55`
- 우선 점검 점수: `0.80`
- PZT 포화 이벤트: 충격은 기록하고 우선 점검으로 표시하되 위치는 `UNKNOWN`

`0.55`와 `0.80`은 안전 인증값이 아니라 현재 축소 시험판에서 상대 점검 우선순위를 나누는 경계값입니다. PZT가 포화되면 충격은 기록하되 위치는 `UNKNOWN`으로 처리하고, 점수와 관계없이 우선 점검 대상으로 표시합니다. 시험 조건과 지표 산출 방법은 [docs/TEST_PLAN.md](docs/TEST_PLAN.md)를 참고합니다.

## 한계와 안전 고지

- 본 시스템은 축소 모형 기반 연구용 프로토타입입니다.
- PZT를 ESP32 ADC에 직접 연결하지 마십시오. 보호 저항, 전압 클램프, 증폭·피크홀드 회로를 거쳐 ADC 입력을 0~3.3V 범위로 제한해야 합니다.
- GPIO34와 GPIO35는 입력 전용입니다.
